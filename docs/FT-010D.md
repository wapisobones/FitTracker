## Preparación y decisiones técnicas

`src/data/core-visual-assets.js` contiene el mapeo explícito de ID, nombre,
prefijo original, slug, textos alternativos y posición elegida para la miniatura.
Lo comparten el manifiesto de runtime y el script de preparación. Los nombres
mostrados no se convierten automáticamente en rutas.

```powershell
pnpm.cmd prepare:exercise-assets
```

Para actualizar solo un ejercicio sin procesar ni reescribir los demás:

```powershell
pnpm.cmd prepare:exercise-assets --only=press-pallof-en-polea
```

La opción acepta únicamente un slug Core registrado y actualiza solo sus dos
WebP, su sección de atribución y el encabezado común, conservando las demás
secciones. Si el ejercicio se incorpora por primera vez, añade su sección.

La utilidad existente `scripts/prepare-exercise-assets.mjs` se extendió para
validar los doce pares contra el catálogo y los nombres reales de archivos.
Los once pares JPG se contrastan con `ejercicios.json`; para los nuevos PNG,
el mapeo explícito local documenta la incorporación posterior. Si cambia el
inventario, falta un archivo o divergen nombre,
ID, fuente o correspondencia, falla antes de escribir los assets. El manifiesto
JSON de originales solo se lee durante preparación, nunca durante el uso web.

Se reutilizan Playwright y Edge instalados, canvas WebP y el contenedor RIFF del
piloto; no hay paquetes nuevos, Python ni FFmpeg. El origen HTTPS sintético del
script se responde localmente con Playwright para usar WebCodecs, sin acceder a
la red. Se decodifican los dos fotogramas de cada animación antes de escribir
los archivos finales. Puede configurarse otro canal Chromium compatible mediante
`PLAYWRIGHT_BROWSER_CHANNEL`.

- **Mismo lienzo del piloto: 640 × 427 px**, calidad WebP 0.78, sin recorte.
- Los originales de Dead bug son 1280 × 720; los de Leñador son
  850 × 1275. Se ajustan conservando la proporción y añadiendo bandas carbón,
  sin deformar la figura. Los demás son 850 × 567 y conservan el escalado y
  redondeo del piloto.
- **Dos fotogramas de 900 ms en bucle: 0 → 1 → 0 → 1…** El retorno a 0 lo
  realiza el bucle del WebP; no se duplica un tercer fotograma ni se alarga
  innecesariamente la pausa en 0. Sin audio ni interpolación.
- La miniatura usa 0 salvo en **Plancha**, donde 0 muestra la preparación de
  rodillas y 1 la postura sostenida. Su tarjeta muestra 1 y la animación mantiene
  0 → 1 → 0.
- Los dos PNG de Plancha alta con toques de hombro son verticales (520 × 676).
  Se conservan completos dentro del mismo lienzo 640 × 427, con bandas carbón.
- La referencia local de Elevación de rodillas se llama **Hanging Leg Raise** y
  el manifiesto suministrado la clasifica como **aproximada**. Esto se indica en
  su detalle y atribución; las instrucciones originales de rodillas flexionadas
  se conservan. Las otras diez correspondencias figuran como exactas.
- Las imágenes son referencias fotográficas. Se conservan íntegros los pasos,
  las recomendaciones y las clasificaciones anatómicas del catálogo.

Los dos assets de Crunch siguen siendo **idénticos al piloto aprobado**:
animación SHA-256 `a2b1e764fb61f7a23fc51d9aed98e412dc9c4de13859eccd8681ee11872de648`;
miniatura `c76723000f30d308b65eec933995591db8121d86c2aec72649bc6b39c051b859`.

## Carga, reproducción, movimiento reducido y fallbacks

Las tarjetas cargan solo fotografías con `loading="lazy"` y dimensiones
explícitas. Abrir un detalle conserva inicialmente la fotografía. **Solo
«Ver secuencia» descarga y reproduce su animación**. Se conserva el control
aprobado «Volver a la imagen» para detenerla; cierre y Escape retiran el recurso,
cancelan sus listeners/timeout y devuelven el foco al disparador.

Se comprueba explícitamente `prefers-reduced-motion: reduce`: se mantiene la
fotografía, se deshabilita «Ver secuencia» y se explica el motivo. Si la preferencia
se activa mientras se reproduce, se detiene la animación y se recupera la imagen.
Al desactivarla se habilita el control, sin iniciar reproducción automática.

Sin recurso registrado se usa el SVG. Si una fotografía falla, se muestra el SVG;
si falla la animación, se recupera la fotografía o su SVG, se anuncia el error y
se permite reintentar. La información técnica permanece disponible. No se cargan
JPG originales ni vídeos del antiguo piloto.

`mediaUrl()` sigue usando `import.meta.env.BASE_URL`, sin barra inicial:
`./assets/exercises/core/...`. Las pruebas sirven el build bajo **`/FitTracker/`**.
